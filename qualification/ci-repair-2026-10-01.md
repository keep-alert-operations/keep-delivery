# Repository CI audit — 2026-10-01

All twelve private repositories in `appchi-alert-operations` were inspected,
including the retained `appchi` monorepo. Each latest workflow/branch result and
its failed steps were inspected; failed logs were read before changing anything.
This record distinguishes hosted job results from additional local verification.

## Repairs and job ownership

`appchi-design/scripts/check_docs.py` still required exactly REV-01 through REV-37
after REV-38 was added for Alembic. The failing command was reproduced, updated to
require REV-01 through REV-38, and rerun successfully. Commit
`7bf631cf8613cca0e10139cc5cd2b391778f9d8e` on `codex/ci-repair` passed
[GitHub Actions](https://github.com/appchi-alert-operations/appchi-design/actions/runs/36890562016).
Delivery's workspace manifest now pins this design commit. The documentation job
remains necessary and active.

The user explicitly chose to retire automatic jobs in the retained monorepo.
Its `application-checks` workflow, ID `366360262`, was disabled through GitHub and
confirmed `disabled_manually`. This retires both legacy backend and frontend
jobs while preserving source and run history. Its prior failures were PostgreSQL
service health-command quoting and frontend formatting; those retired copies were
not repaired. The independent repositories own the current checks.

Eight workflows initially failed before their checks because
`APPCHI_REPOSITORIES_TOKEN` was unavailable. Their dependency locks reference
private sibling repositories, so these jobs and their authentication requirement
were retained. With the user's explicit approval, a dedicated fine-grained token
was created with read-only Contents/Metadata permission for the eleven selected
workspace repositories, expiring 2026-12-30. It was saved as an encrypted repository
secret in all eight consumers. GitHub Free does not make organization secrets
available to these private repositories. No general-purpose developer login token
was reused, and no token value was committed or included in this evidence.
See [consumer repositories, access scope and rotation instructions](../docs/repository-workspace.md#build-and-ci).

After credential setup, seven workflows passed immediately. Frontend's rerun
exposed a second authentication problem: `actions/checkout@v4` persisted a
repository-scoped `GITHUB_TOKEN` authorization header, overriding the credential
helper when npm fetched private contracts. The failed log showed the persisted
header and `Repository not found` during `git ls-remote`; the action's
[authentication implementation](https://github.com/actions/checkout/blob/v4/src/git-auth-helper.ts)
confirmed how that header is set. Frontend commit
`468ba80eeac6ca2ad4b95752edb7b8005aa354fb` sets `persist-credentials: false`.
The subsequent hosted install, generation/drift, formatting, types and build all
passed. Delivery now pins this frontend revision; no application source changed.
